# [021] خارطة الطريق v2 — خطة التحسينات الثمانية (Roadmap v2: Eight-Phase Plan)
- **التاريخ**: 2026-09-06 21:30 (UTC+3)
- **الوكيل المنفذ**: opencode (GLM)
- **الحالة**: معتمدة من المالك — تحت التنفيذ

## المرحلة 1 — صفحة الدخول بمستوى sendrad.com
- تخطيط مقسوم: لوحة أنيميشن تعرض محاكاة حية للمنتج (محادثة AI + عداد عملاء) + لوحة النماذج
- اللوجو النصي الموحد `hudhud.` (المعتمد من الـ landing) في كل الموقع — إلغاء لوجو "HH" المبتكر
- اختيار دولة كامل: 200+ دولة، أعلام، بحث بالاسم (عربي/إنجليزي) وبكود الهاتف مع إكمال تلقائي
- دمج صفحة auth في محرك i18n المركزي (نسختا AR/EN حقيقيتان)
- أنيميشن دخول ناعم + micro-interactions

## المرحلة 2 — التدقيق الشامل لجداول Supabase
- تقرير لكل جدول: الغرض، الأعمدة، RLS/grants، العلاقات، الفهارس، مسار الاستخدام في الكود
- ERD Diagram بصيغة Mermaid في PROJECT_BRAIN
- كشف: جداول ميتة، تكرار، علاقات ناقصة، ثغرات RLS (خصوصاً USING(true))
- migration إصلاحي يطبق على الحية

## المرحلة 3 — يوزران اختباريان + مصفوفة الصلاحيات
- admin.test + user.test على الإنتاج
- فحص كل صفحة × API × الدورين + محاولات تجاوز
- تقرير bugs وإصلاح فوري

## المرحلة 4 — Google OAuth
- تفعيل Google Provider الأصلي في Supabase Auth (مجاني)
- إرشاد المالك لإنشاء OAuth Client في Google Cloud Console
- مزامنة المستخدم مع جدول users (نفس الأدوار والجلسات)
- زر "المتابعة بحساب Google" في صفحات الدخول/التسجيل

## المرحلة 5 — RAG بـ pgvector (معتمد بدل LEANN)
**قرار مأسوس بدراسة كاملة لمستودع LEANN**: يتطلب تجميع C++ وفهرس قرص محلي ووضع جهاز شخصي — مستحيل على Vercel serverless.
- تفعيل pgvector في Supabase + جدولا kb_documents / kb_chunks (embedding vector)
- Embeddings عبر Gemini text-embedding-004 (API رخيص) عند الرفع
- بحث هجين: cosine + tsvector + دمج RRF
- نقل المعرفة من ملفات markdown إلى DB — **يحل مشكلة read-only نهائياً**
- **حذف المعرفة الوهمية الحالية** (لا علاقة لها بالبزنس)
- **محلل Gemini البنيوي** للمنشورات والكومنتات: لكل بوست (ماذا نشر؟ ماذا وعد؟ ما CTA المطلوب؟) وتصنيف كل تعليق (رد CTA / سؤال حقيقي / شكوى / سبام) مع استشهاد إجباري بأرقام البوستات والكومنتات — صفر تخمين
- ⚠️ تصميم برومبت التحليل سيُعرض على المالك للموافقة قبل التنفيذ

## المرحلة 6 — حزمة Meta App Review (سر الربط السحابي)
- تحضير: نصوص تبرير الصلاحيات + سيناريو فيديو العرض + Privacy Policy ✓ + Data Deletion ✓
- التوثيق التجاري المبسط: هاتف العمل (SMS) + إيميل + التحقق من الدومين — الأوراق استثناء نادر
- بديل مؤقت: وضع التطوير + Testers (~100 مستخدم) يكفي لبداية البيع اليدوي

## المرحلة 7 — تنبيهات الأدمن الذكية
- مراقبة: Threads token (<14 يوم + زر تجديد)، Meta token، الويب هوك، حصص Gemini، آخر تشغيل سكيدولر، حداثة Insights، اتصال Supabase
- شرائح ملوّنة في لوحة الأدمن + cron يومي للفحص

## المرحلة 8 — نظام AI Providers بأسلوب opencode (الأضخم)
- جدولا `ai_providers` + `ai_models` (ترحيل SQL)
- مزودون رسميون بلوجات SVG مدمجة: Google AI، Anthropic، OpenAI، OpenRouter
- **اكتشاف تلقائي**: عند الحفظ/تسجيل الدخول/زر "تحديث الاتصال" → سحب قائمة الموديلات من API المزود وتحديد المتاح فعلاً — غير المتاح لا يظهر للعميل
- **Custom Provider** بنموذج opencode حرفياً: Provider ID + Display name + Base URL + API key (اختياري) + +Add model متعدد + +Add header متعدد (كله optional)
- تفعيل/تعطيل كل موديل من الأدمن → ينعكس على واجهة اختيار "عقل الوكيل" للعميل فوراً
- محرك موحد `llm_router` يخاطب: صيغة Gemini / OpenAI-compatible / Anthropic
- الأمان: المفاتيح لا تعود للواجهة (مقنّعة) ولا تُرفع لـ git
