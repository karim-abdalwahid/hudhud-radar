# 🛡️ SOP-11: سلامة الأوامر في PowerShell (لا أوامر Python طويلة inline)
#sop #powershell #python #tooling #قاعدة-دائمة

- **المعرف**: `SOP-11`
- **الحالة**: نشط وإلزامي (Active & Enforced)
- **الاعتماد**: بأمر المالك (2026-09-11) بعد تكرار فشل `The request is invalid: read body failed`

---

## 1. القاعدة الذهبية (ممنوع مخالفتها)

> **ممنوع نهائيًا** كتابة أوامر Python/Node الطويلة inline جوه PowerShell — مثل:
> ```powershell
> python -c "import json; d = {'key': 'value'}; print(f\"{d}\")"
> ```
> الاقتباسات المتداخلة (`"` + `\"` + `'`) وعلامة `&` والـ triple-quotes بتكسر تحليل PowerShell → أخطاء `The request is invalid` / `Missing terminator` / `Ampersand not allowed`.

## 2. الإجراء الإلزامي

1. **اكتب الكود في ملف** بأداة الكتابة (Write tool) — دائمًا UTF-8:
   ```
   scripts/tmp_task.py   (أو اسم وصفي في جذر المشروع)
   ```
2. **شغّله**:
   ```powershell
   python scripts/tmp_task.py
   ```
3. للمهام السريعة جدًا (سطر واحد بسيط بدون اقتباسات متداخلة ولا `&`): يُسمح بـ inline **فقط** إذا كان النص أقصر من ~120 حرفًا ويستخدم اقتباسًا واحدًا على الأكثر.

## 3. لماذا (السياق)

- PowerShell يتعامل مع `"` و `'` و `&` بشكل مختلف عن Bash — أي تداخل بينهم في أمر واحد = parse error.
- تكلفة الفشل: ضياع وقت + رسائل خطأ مربكة للمالك في الشات + احتمال تنفيذ جزئي غلط.
- **البديل الموثوق المُثبت**: ملفات سكربتات — 6 عمليات متتالية بصفر أخطاء بعد التطبيق.

## 4. الاستثناءات
- `rg`/`Get-Content`/`Get-ChildItem` القصيرة — عادية.
- سكربتات المشروع الدائمة (audit_*.py إلخ) — هي نفسها الإثبات أن الملفات هي الأسلوب الصحيح.
