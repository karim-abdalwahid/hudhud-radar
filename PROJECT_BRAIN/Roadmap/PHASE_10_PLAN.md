## 📊 1. ربط بيانات الإعلانات (PostHog Data Warehouse × Meta Ads)

**الفكرة**: توصيل مصدر Meta Ads في PostHog Data Warehouse لربط أداء الإعلانات بسلوك العملاء داخل المنصة (أي حملة جابت عملاء يدفعون فعلًا).

### شروط مسبقة إلزامية (قاعدة المالك — لا استثناء)
1. وجود عملاء فعليين + ميزانية إعلانية نشطة (الشيفرة لا تُكتب قبلها).
2. **تحديث سياسة الخصوصية (عربي/إنجليزي) قبل أي اتصال** — إفصاح صريح عن مشاركة مصادر البيانات الإعلانية مع PostHog (استضافة EU).
3. قرار واعٍ موثق في PROJECT_MEMORY قبل التنفيذ (نمط SOP-01).

### مخاطر معروفة (تُراجع وقت التنفيذ)
- مشاركة بيانات PII مع طرف تالث — يُفضل ربط بيانات مجهولة الهوية فقط (campaign_id / utm بدون إيميلات).
- ربط الإعلانات يعمل مع Meta Ads — مدفوعاتنا Polar (لا Stripe) → الربط يكون إعلانات↔سلوك، لا إعلانات↔مدفوعات مباشرة.

## 🤝 2. برنامج الأفلييت (Affiliate)
- تتبع إحالات (referral codes/links) → منح عمولات أو credits عند أول دفعة.
- يحتاج: جدول referrals + صفحة تسويقية + إعدادات عمولة في admin.
- مربوط بنظام الفوترة الحالي (user_entitlements/coupons — platform_unlock جاهز كنموذج).

## 🔗 3. أدوات تسويقية مرتبطة (جاهزة جزئيًا من 9.6/9.7)
- PostHog: قمع البيع (تسجيل→تجربة→دفع→ربط) يقيس أثر الإعلانات على التحول.
- بطاقات الـ upsell (اكتشاف IG من ربط FB) = أداة تحويل داخلية تدعم عائد الإعلان.

## 🧩 4. Leads صفحة — فلتر المنصات (طلب المالك 2026-09-11 — مسجل للتخطيط، غير مجدول)
- **المطلوب**: في صفحة /leads — فلتر لعرض العملاء حسب منصة المنشأ (Facebook / Instagram / Threads / الكل) بدل عرض الجميع دائمًا.
- **التصميم المقترح**: قائمة فلاتر (chips) أعلى القائمة تُغذي بارامتر platform في API الـ leads (get_all_leads يدعم فلترة user_id بالفعل — يضاف فلتر source) + عداد لكل منصة + حالة 'الكل' افتراضية.
- **الحالة**: بانتظار جدولة المالك (بند تخطيطي فقط — لم يُنفذ).
