## 👥 1. إدارة الأدوار والصلاحيات (Role Management)

### الأدوار المستهدفة
| الدور | الوصف | الصلاحيات |
|---|---|---|
| `admin` | مالك المنصة / ثقة كاملة | كل شيء (الوضع الحالي) |
| `developer` | فريق تقني موثوق | صفحات التشخيص والقوالب والمعرفة — **قراءة/صيانة**، بدون: المستخدمين، الفوترة، الحذف، إعدادات الدفع |
| `user` | عميل | الوضع الحالي (عزل per-user) |

### المتطلبات
1. **جدول المستخدمين**: `users.role` يمتد لقيم `(admin, developer, user)` — migration 012 (ALTER TYPE / CHECK).
2. **واجهة الإدارة**: صفحة `/users` الحالية → قائمة منسدلة لدور كل مستخدم + تأكيد قبل الحفظ.
3. **القواعد الحاكمة (صارمة)**:
   - ممنوع تخفيض **آخر أدمن** في المنصة (حماية من الإغلاق الخارجي).
   - ممنوع للمستخدم تغيير دوره هو بنفسه.
   - كل تغيير دور يُسجل في `activity_logs` (من غيّر، مين اتغير، من إيه لإيه).
   - المصفوفة الكاملة لصلاحيات `developer` تُراجع مع المالك قبل التنفيذ (تمهيد لنظام permissions تفصيلي لو اتطلب).
4. **Backend**: `PATCH /api/admin/users/{user_id}/role` + helper للتراتب (`role_level`) يُستخدم في auth middleware بدل فحص `role != 'admin'` الثابت.
5. **اختبارات**: ترقية/تخفيض · حماية آخر أدمن · حماية النفس · developer ممنوع من الفوترة والمستخدمين · كل تغيير مسجل.

## 💉 2. حقن أكواد مخصصة (Custom Snippets — header/body)

### الفكرة
المالك يضيف أكواد (HTML/JS/CSS — مثل Google Analytics، Meta Pixel، أدوات دردشة، verification tags) تُحقن في الموقع **دون تعديل أي ملف في الكود الأساسي**، وتُخزن في قاعدة البيانات، وتُدار بالكامل (إضافة/تعطيل/حذف) من صفحة الأدمن.

### التخزين (persistent — ينجو من الـ deploys)
```
app_settings → key: "custom_snippets" → JSON:
[{
  "id": "uuid",
  "name": "Meta Pixel",
  "placement": "header" | "body_end",
  "enabled": true,
  "code": "<script>...</script>",
  "created_at": "...", "updated_at": "..."
}]
```

### آلية الحقن الآمن (الحوكمة الأساسية)
1. **نقطة الحقن الواحدة**: طبقة عرض القوالب (pages/templates_manager) تحقن الـ snippets قبل `</head>` (header) وقبل `</body>` (body_end) عند كل طلب — **صفر تعديل في ملفات الكود أو القوالب الثابتة**.
2. **لا تكسير ممكن للموقع**: الحقن عملية نصية على الـ HTML الناتج — مفيش تنفيذ Python داخل السنيبت؛ لو marker مش موجود (`</head>`) → تخطي مع log تحذيري، الصفحة تظل تخدم عادي.
3. **حذف بضغطة زر**: من صفحة الأدمن — الحذف من app_settings → الموقع يتقدم فورًا بدون السنيبت (العرض يقرا الإعدادات لحظة الطلب — لا deploy مطلوب).
4. **تعطيل مؤقت**: toggle enable/disable بدون حذف (استرجاع فوري).
5. **حدود**: حد أقصى لحجم السنيبت (مثلاً 50KB) + حد العدد (مثلاً 20) — حماية من الأخطاء غير المقصودة.
6. **سجل تدقيق**: كل إضافة/تعديل/حذف → `activity_logs`.
7. **تنبيه خصوصية**: أي سنيبت بيضيف تتبع خارجي = مسؤولية المالك بتحديث سياسة الخصوصية (نفس نمط PostHog — [[SOP_10_Custom_Code_Injection]]).

### واجهة الأدمن (صفحة موجودة تتمدد — templates_manager أو صفحة جديدة /admin/snippets)
- قائمة السنيبتات: الاسم، المكان (header/body)، الحالة (مفعل/معطل) — أزرار: تعديل / تعطيل / **حذف (تأكيد واحد)**.
- نموذج إضافة: اسم + اختيار المكان + مربع الكود + معاينة قبل الحفظ.
- الحذف والتغيير يظهران فورًا على الموقع بدون إعادة نشر.

### اختبارات (~12)
حقن header/body في صفحة حية · عدم الحقن لما معطل · الحذف يزيله فورًا · سنيبت مكسور (JS غلط) لا يوقف الصفحة · marker مفقود → تخطي + log · حدود الحجم/العدد · سجل التدقيق لكل عملية · الصلاحيات (user ممنوع 403).

### تسلسل التنفيذ
1. Migration (لو لزم) + مخزن app_settings + Service (CRUD + حدود) — [[SOP_10_Custom_Code_Injection]]
2. نقطة الحقن في طبقة العرض + guard tests
3. صفحة الأدمن (قائمة/إضافة/تعديل/تعطيل/حذف)
4. أدوار المستخدمين (migration 012 + role_level + صفحة /users + قواعد الحماية)
5. توثيق كامل (Memory + Brain + Activity Log — SOP-01 خطوة 6)
